## Guidance

What to press when an agent is stopped at a screen. Each entry names the screens it covers and what to do. A screen that no entry covers is not yours to decide: press nothing and ask the people.

- Claude Code's folder-trust dialog ("Accessing workspace:", then the directory, then "Quick safety check"): trust it only when the directory it names is the stopped agent's own working directory. For any other directory, press nothing and ask.
- A question whether to trust a file, or whether to allow reading or writing a file: allow it. This covers trusting, reading and writing files only, never a confirmation to run a command.
- A confirmation to run a command that Claude Code itself flags as possibly unsafe or as one it could not check, with a countdown to deny it automatically (for example "could not be checked"): press nothing and let it be denied. The stopped agent gets the denial and goes on with a safer command of its own. With such a countdown this entry decides, even when another entry covers the command. Without one, press nothing and ask, unless another entry covers the command.
- A confirmation to run a command, without a countdown to deny it, where the command deletes, overwrites or empties a file at a target that is not checked: press `No`, and ask nothing. Decide it from the command as the screen shows it, a script inside `sh -c`, `bash -c` or `eval` included:
  - The command deletes, overwrites or empties a file when it runs `rm`, `rmdir`, `unlink`, `shred`, `truncate`, `mv`, `cp`, `tee` without `-a`, `rsync` with `--delete`, or `find` with `-delete` or with an `-exec` or `-execdir` that runs one of these, or when it has a `>`, `>|` or `&>` redirection, or a `>&` to a file (with or without a descriptor number before it; not `>>` or `&>>`, and not `>&` to a descriptor such as `2>&1`). It runs one of these programs when the program's name is the first word of a simple command, after any `NAME=value` assignments and after `sudo`, `env`, `command`, `exec`, `nohup`, `time` or `xargs` with their options (and, for `env`, its `NAME=value` operands); a subcommand of another program, such as `git rm`, is not that program. Its targets are every path operand of `rm`, `rmdir`, `unlink`, `shred`, `truncate`, `mv` and `tee`, the last path operand of `cp` and `rsync`, the start paths of `find`, and the word after the redirection.
  - A target is checked only when it has no command substitution (`$(…)` or a backtick), and every `$` in it starts a `${NAME:?}` or a `${NAME:?message}` whose `NAME` the command either does not set with `NAME=…` or sets only to checked values. A value is checked when it has no backtick, and every `$` in it starts such a `${NAME:?…}` or a `$(…)` in which every `$` again starts such a `${NAME:?…}`. So after `d=$(dirname "$p")`, `${d:?}` is not checked (with `$p` empty, `dirname` gives `.`, which `${d:?}` lets through), while after `d=$(mktemp -d)` or `d=$(dirname "${p:?}")` it is. A test before it, such as `[ -n "$d" ] &&`, does not check it. A target with neither `$` nor a backtick is checked.
  - Covered (press `No`): `p=$(ls -td /tmp/tmp.*/probe.py | head -1); d=$(dirname "$p"); [ -n "$d" ] && rmdir -- "$d"`; `d=$(dirname "$p"); rm -rf -- "${d:?}/build"`; `rm -rf "$d/build"`; `rm -rf -- "${d:?}/$(cat name)"`; `sudo mv "$tmp" /srv/a.json`; `make &> "$log"`.
  - Not covered by this entry: `rm -rf build`; `rm -rf -- "${d:?}/build"`, when the command does not set `d`; `d=$(mktemp -d) && rm -rf -- "${d:?}"`; `rm -f /tmp/report.txt`; `git rm -r "$d"`; `make > /dev/null 2>&1`; `cat "$f"`.
  - To press it, find on the screen the option whose text starts with `No` (its number varies, for example `2. No` or `3. No, and tell Claude what to do differently (esc)`) and press its digit; when the confirmation is still there with the cursor on that option, press `enter`. Press no other option.
  - Then read the screen again and record the command, the target that is not checked and what the stopped agent did: when its input box shows with nothing running, write that it was refused and waits for a message (Claude Code tells an agent whose own command is refused to stop and wait for the user); otherwise write that it went on (a subagent whose command is refused is told to try another way).
- A confirmation to run a command (for example "Bash command", the command, "Do you want to proceed?"): decide only when another entry here covers that command; otherwise press nothing and ask.
- A usage or rate limit, a model switch, a usage reset, or anything that buys or adds usage: never press anything; ask. Only a person deals with these.
